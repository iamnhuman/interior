# IFC, SKP и веб-просмотр архитектурной модели

Исследование от 22 октября 2026 года. Вывод основан на содержимом двух файлов, фактическом разборе геометрии и первичных источниках библиотек.

## Выбор для этой задачи

**Для структуры, слоёв, идентификации объектов и BIM-свойств лучше `T2_Ap.ifc`. Для исходного оформления лучше `T2_Ap+.skp`. Для доставки геометрии с текстурами в браузер удобен GLB.**

Это разные роли: IFC и SKP — исходные модели, GLB — подготовленный формат для веб-просмотра. Не нужно выбирать один исходник и отказываться от другого. В сайте доступны оба, каждый подготовлен подходящим способом.

| Проверено в файле | `T2_Ap.ifc` | `T2_Ap+.skp` |
| --- | --- | --- |
| Размер исходного файла | около 14 МиБ | около 7,4 МиБ |
| Формат | IFC2X3, экспорт ARCHICAD 22 | классический SketchUp, заголовок `{13.0.1}` |
| Именованные слои | 6 | 8, включая Layer0 и оси |
| Материалы | 10 стилей поверхности; отдельно 4 IfcMaterial | 11 исходных материалов, 10 использованы в подготовленной сцене |
| Изображения текстур | отсутствуют | 2: потолочная плитка и светлая обшивка |
| Геометрия | 186 элементов, 890 частей, 133 320 треугольников после web-ifc | 566 определений; 567 узлов с корнем и 490 ресурсов мешей в GLB |
| Данные объектов | IFC-тип, GlobalId, Express ID, связи и параметры | группы, компоненты, слои и размещения |
| Единицы | миллиметры в исходнике; web-ifc выдаёт метры | дюймы внутри формата; конвертер выдаёт метры, Y-up |
| Готовые размерные цепочки | IFC Annotation отсутствует; экспорт 2D-аннотаций выключен | наличие графических размеров нельзя приравнивать к полноценному чертежу; сайт вычисляет свои измерения |

Больше узлов или меньше размер файла сами по себе не означают большую точность. Сегментация геометрии в форматах различается. Модели центрируются для просмотра независимо; автоматическое совмещение и доказательство идентичности двух версий не выполнялись. Габариты по глобальным осям могут отличаться из-за ориентации модели.

## Что обнаружено в IFC

Есть один `IfcBuildingStorey` — «1-й этаж». Слои:

| Исходный слой | Элементов с отображаемой геометрией |
| --- | ---: |
| Конструктив - Колонны | 2 |
| Конструктив - Навесные Стены | 83 |
| Интерьер - Мебель | 68 |
| Отделка - Потолок | 1 |
| Конструктив - Перекрытия | 2 |
| Конструктив - Стены Несущие | 30 |

Группировка извлекается из `IfcPresentationLayerAssignment`, а не восстанавливается по цвету. Число элементов на слое не обязано совпадать с числом объектов отдельного IFC-класса. В частности, часть объектов экспортирована как `IfcBuildingElementProxy`; слой «Мебель» включает и другие типы.

Стили содержат цвета и прозрачность стекла, но `IfcImageTexture` и `IfcSurfaceStyleWithTextures` отсутствуют. Поэтому включение «текстур» на исходном IFC не может показать отсутствующие изображения. Для этого нужны новые текстуры, соответствующий экспорт или SKP.

Параметры экспорта в заголовке прямо указывают, что аннотации ARCHICAD и 2D-элементы не экспортировались; базовые количества также выключены. Для будущего BIM-сценария стоит включить необходимые свойства и количества в исходном CAD-экспорте. Это не препятствует измерению расстояний по имеющейся геометрии.

Парсер web-ifc выводит `No basis found for brep` для некоторых контуров. Все 186 элементов вернули непустую геометрию, но отдельные вырожденные грани могут быть пропущены. Поэтому отсутствие ошибок нашего бинарного кэша не является проверкой полного совпадения с исходной CAD-моделью.

## Что обнаружено в SKP

Файл содержит восемь слоёв: шесть содержательных архитектурных слоёв, Layer0 и «Элемент Модели - Оси». Оси и пустые слои не становятся отдельными поверхностями в GLB, поэтому интерфейс показывает слои с отображаемыми мешами.

Сохранены материалы «Краска - Белила Титановые», «Потолок - Плитка 60x120», «Краска - Глянцевая Белая», «Краска - Светло-Серая», «Металл - Сталь Нержавеющая», «Стекло - Прозрачное Быстрое», PEN_MATERIAL1, «Краска - Темно-Серая», «Металл - Алюминий», «Краска - Антрацит», «Обшивка - Светлая».

Изображения привязаны только к двум материалам. Следовательно, SKP не содержит полного набора фотореалистичных покрытий на все поверхности. Дерево, бетон и другие варианты в библиотеке сайта — добавленная процедурная отделка, а не найденные исходные материалы.

Проверка OpenSKP дала практическое различие между версиями: пакет 1.3.0 из npm падает на старом контейнере с `legacy_walk / expected a string record`. Текущая исходная ревизия `23a15e8742e936694bf14aa029cb0e2862dce5b9` успешно разбирает этот файл. Рабочий конвертер закреплён в проекте, поэтому сайт не зависит от будущего состояния ветки main. OpenSKP — независимый парсер, созданный обратной разработкой; это не SDK Trimble. Его поддержка других SKP-файлов требует проверки на этих файлах. [Исходники и описание OpenSKP](https://github.com/iamahsanmehmood/openskp), [текущие ограничения](https://github.com/iamahsanmehmood/openskp/blob/main/ROADMAP.md).

В [документации SketchUp по GLB](https://help.sketchup.com/en/sketchup/working-gltf-files) GLB описан как единый бинарный файл с геометрией и текстурами для интерактивных приложений. Нативный экспорт из актуального SketchUp может стать альтернативой независимому парсеру, если появятся файлы, которые OpenSKP не читает.

## Реализованный путь

1. IFC разбирается `web-ifc`; сохраняются геометрия, преобразования, исходные слои, имена, типы и идентификаторы. Кэш состоит из JSON и бинарных массивов. Полный IFC-граф свойств в интерфейс не выводится.
2. SKP преобразуется в GLB с сохранением повторного использования геометрии, размещений и двух изображений. Исходный слой и ID узла добавляются в glTF `extras`. Это обеспечивает выбор и скрытие элементов после конвертации.
3. Three.js отображает обе модели. Исходные материалы отделены от пользовательских назначений. Белый режим и отключение текстур не меняют исходники.
4. Для новых покрытий используется трёхплоскостная проекция в координатах модели. Она позволяет накладывать плиточное изображение даже на IFC без UV. Масштаб задаётся в метрах. Для сложных авторских раскладок и точного направления древесных волокон потребуется подготовленная UV-развёртка.
5. Линейка измеряет евклидово расстояние между точками; рядом с вершиной работает экранная привязка. Переключатель «Габариты» показывает ограничивающий параллелепипед выбранного элемента либо всех видимых слоёв. Это не чистые размеры проёмов и не строительные размерные цепочки.
6. Разрез обрезает геометрию выбранной плоскостью. Заполнение сечения и построение чертежа не реализованы.

## Проверка и пределы результата

Успешно прошли сборка Vite, одиннадцать тестов геометрии, данных, настроек отображения и путей статического сайта и полный [валидатор Khronos glTF](https://github.com/KhronosGroup/glTF-Validator). У GLB 0 ошибок и 0 предупреждений; информационные сообщения относятся к UV у одноцветных поверхностей и одному изображению с размерами не степеней двойки. Модель использует метры; проверена общая высота 5,4 м после преобразования IFC.

Локальный сервер проверяется HTTP-запросами к странице, подготовленным моделям, JavaScript и WebAssembly. По инструкции пользователя браузер не открывается. Поэтому внешний вид, фактическое GPU-отображение, работа мыши/жестов и поведение конкретного браузера не отмечены как визуально проверенные. Изменения материалов сохраняются только до перезагрузки страницы.
