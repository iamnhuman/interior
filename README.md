# ATELIER — архитектурная мастерская T2

Статический сайт для двух моделей из этой папки. В корне репозитория уже лежат готовый `index.html`, скрипты, стили, модели и WebAssembly. Для размещения на GitHub Pages не нужны Node.js, сервер приложений или сборка на GitHub. Исходные `T2_Ap.ifc` и `T2_Ap+.skp` сохранены; подготовленные веб-копии находятся в `public/models/` и в статическом каталоге `models/`.

## Готовый сайт и GitHub Pages

Корневая точка входа — `index.html`. Все пути относительные, включая модели, Web Worker и IFC WebAssembly, поэтому сайт работает и в `/interior/`, и в корне домена. `.nojekyll` отключает обработку Jekyll.

В настройках GitHub Pages можно выбрать ветку `main` и каталог `/(root)`. Настройки Pages и автоматическое развёртывание кодом проекта не меняются; workflow для публикации не добавлен.

Чтобы посмотреть готовую статическую версию локально без npm:

```bash
python3 -m http.server 5174 --bind 127.0.0.1
```

Откройте http://127.0.0.1:5174/. Страница рассчитана на HTTP/HTTPS: прямой `file://` ограничивает загрузку моделей и WebAssembly политиками браузера.

## Разработка

```bash
npm install
npm run dev
```

Vite напечатает локальный адрес, обычно http://127.0.0.1:5173. Для разработки требуется Node.js 20.19+ или 22.12+; для просмотра — браузер с WebGL 2. Исходный HTML находится в `src/index.html`. Команда `npm run build` собирает `dist/` и обновляет готовый сайт в корне репозитория. Редактировать готовый корневой HTML вручную не нужно. Просмотр сборки: `npm run preview`.

После правок перед коммитом выполните:

```bash
npm run build
npm test
npm run check:static
```

Сборка удаляет только устаревшие файлы, перечисленные в `.static-files.json`, и обновляет созданные ею статические файлы. `assets/`, `models/`, `favicon.svg`, `index.html`, `.nojekyll` и `.static-files.json` входят в Git. `node_modules/`, `dist/` и `.cache/` не публикуются в репозитории.

Что доступно:

- Переключение IFC и SketchUp; открытие своих IFC, SKP и GLB с устройства.
- Вращение, масштаб, перемещение; аксонометрия, ортогональные виды и свободный полёт камеры без привязки к центру модели.
- Включение отдельных исходных слоёв. Потолок при открытии скрыт.
- Режимы «Оригинал», «Отделка» и белый «Макет»; независимые переключатели текстур, контуров и габаритов.
- Выбор элемента с отображением слоя, ID, материала и габаритов. При включённых «Габаритах» наведение показывает размеры объекта, подсказку и рамку; выделение для материалов сохраняется.
- Четыре процедурных покрытия, готовая палитра и загрузка изображения. Покрытие назначается элементу или всему его слою; регулируется размер повтора в метрах.
- Разрез по X, Y или Z и линейка между двумя точками с привязкой к вершинам в пределах 12 экранных пикселей.
- `F` — вписать модель; `M` — линейка; `V` — включить/выключить полёт; `1` — 3D; `2` — план; `Esc` — вернуться к вращению, выйти из линейки и снять выделение; двойной щелчок — приблизить элемент.

Вращение — левая кнопка мыши; перемещение — правая; масштаб — колесо. На сенсорном экране поддерживаются жесты OrbitControls. Изменения отделки и добавленные модели живут в текущей сессии страницы. Постоянное сохранение вариантов в этой версии не реализовано.

В режиме полёта: нажмите на 3D-вид, затем используйте WASD для движения, Q/E для снижения/подъёма, Shift для ускорения ×4, правую кнопку мыши или стрелки для поворота взгляда, Z/C для наклона камеры. Колесо перемещает вперёд/назад. Скорость регулируется в метрах в секунду; кнопки на панели позволяют летать мышью или касанием. На сенсорном экране направление взгляда меняется перетаскиванием. При потере фокуса движение останавливается. Возврат к вращению сохраняет текущую позицию и ориентацию камеры; выбор стандартного ракурса или команда F возвращают обычную навигацию.

Размеры при наведении — габариты объекта по мировым X/Y/Z в метрах. Скрытые слои и отсечённые плоскостью поверхности не участвуют в наведении. На пустом месте снова показываются размеры выделенного объекта или всей видимой модели. Наведение не изменяет материал и не переключает выбор объекта в инспекторе.

## Какой файл подходит лучше

Результат исследования именно этих файлов и сравнение существующих реализаций: [RESEARCH.md](./RESEARCH.md).

IFC — основа для BIM-структуры и свойств. SKP содержит больше исходного оформления. Для браузерной доставки SKP преобразован в GLB с изображениями и метаданными слоёв; IFC заранее подготовлен в геометрию и JSON, чтобы не выполнять разбор при каждом открытии. Загрузка новых файлов обрабатывается в Web Worker.

## Обновление моделей и проверки

```bash
npm run analyze
npm run prepare:models
npm run build
npm test
npm run check:static
```

После замены исходников выполните `prepare:models`. Проверки фиксируют состав текущих образцов, геометрию, слои, масштаб и наличие двух текстур, а также точность глубины и настройки стекла и теней. При намеренной замене модели ожидаемые числа в тестах нужно обновить. GLB проходит официальный `gltf-validator` Khronos: 0 ошибок, 0 предупреждений. Есть информационные сообщения о неиспользованных UV у одноцветных материалов и размере одной текстуры.

Для уменьшения мерцания при движении используется логарифмический буфер глубины и диапазон камеры под размер модели. Стекло не записывает глубину, не получает непрозрачные тени и рисуется за один проход. У непрозрачных элементов тени строятся по обратным граням, а камера теней охватывает габариты модели. Исходная настройка сторон материалов GLB сохраняется и в режиме макета.

Используются Three.js, web-ifc и OpenSKP. Закреплённая рабочая версия OpenSKP находится в `vendor/openskp/` вместе с MIT-лицензией и номером ревизии. Версия OpenSKP 1.3.0 из npm не читает этот старый SKP; свежий исходный код читает. Конвертация проходит на компьютере, модели в сторонние сервисы не отправляются.

У web-ifc есть сообщения `No basis found for brep` на части вырожденных контуров IFC. Все 186 элементов дали геометрию, но это не гарантирует сохранность каждой отдельной грани. Размеры являются вычисленными габаритами или расстояниями по отображаемой геометрии, а не размерными цепочками исходного чертежа. Разрез не строит заполнение сечения. Исходная BIM-модель и CAD-чертежи остаются источником проектной документации.

Браузер, визуальная проверка и проверка скачиваний не запускались согласно инструкции проекта. Проверены данные, конвертация, сборка, тесты и HTTP-ответы локального сервера.
